# Page Lens connection review

This source feature requires review of the extension permission changes before loading or running the new extension. It has not been browser-tested or activated by these source changes.

An owner creates a one-use pairing handoff lasting ninety seconds. The connection page sends it only through a nonce-bound event to the extension's explicitly opened connection tab; it is absent from URLs. The enabled source-tab session lasts at most ten minutes. The capability is stored hashed server-side, sent in an Authorization header by the extension, and cannot create library sessions or obtain a card, cookie, prose, arbitrary JavaScript, navigation, scrolling, frame contents or direct stream URLs.

Owner controls require the authenticated owner identity in the same room. Another authorised device of that owner can request capture. Every extension operation rechecks the original pairing browser session, owner membership, expiry and the paired extension origin. Revoking that session, membership or connection closes the capability.

The explicit local Reading Room pairing confirmation selects the exact originally enabled tab after validating the nonce and API pairing response; it does not change that tab’s URL or focus/restore its window. Remote commands never activate tabs, navigate or scroll. Before and after capture, the extension checks the exact source URL, selected tab in its original window, unminimized window, and rendered DOM visibility/viewport hit-testing. OS foreground-app focus is not verified: the result describes the rendered enabled-tab viewport, not a physical-screen screenshot. Each fixed command is claimed once, expires after ninety seconds, and accepts one bounded result. There can be one pending command and at most twenty commands per connection. Results contain at most twenty safe image/player references and captions, never article paragraphs. Media references may be private room content: result retrieval requires the room owner, and import remains an explicit reviewed action through the existing room API. Nothing auto-imports.

Session and command records expire after ten minutes. Expired records are removed when a new connection is created; this is request-time cleanup, not a guaranteed background deletion job. No capability tokens or article content are logged by this API. Preserve the exact host allowlist and content-script nonce checks when configuring a new deployment origin. The existing site origin is the default; custom-domain TLS/provider status is a separate deployment check.

A live 0.2.3 owner report confirms one Telegraph media result reached review on the second request, after a first capture-failed attempt; the source remained open/front on the Mac. D1 metadata recorded one video reference with a caption and no poster/separate image. The owner reports the video appeared in Reading Room; native worker logs record the room-capture POST returning HTTP 200. Inline playback failed, then the owner reports success through “Open original player” on the tested phone. This is not an independent Danielka-device check and does not verify original placement, image fidelity, or background/unfocused Chrome behavior. Before broader owner acceptance, verify permission text, inactive-tab/minimized-window refusal, URL-change refusal, Stop/expiry/revocation, command replay, room isolation, provider behavior and a named recipient-device check. Reading Room version 51 makes “Watch video on Telegraph” the primary action, retaining that exact original-player URL, with embedded playback behind an initially closed optional control. The changed button itself has not been retested on the phone; no CSP, referrer, permission or authentication changes were made. A successful 0.2.2 pairing/polling check alone was not evidence of media capture. Synthetic tests establish protocol behavior, not those live outcomes.
