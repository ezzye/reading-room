Reading Room · proposed approach

Let a real browser read the page

A server-side rendered-browser capture is a better main route for article presentation and media than asking someone to keep a desktop tab active. It can load the ordinary public page, wait for its content to settle, and record what that browser actually receives. It still cannot promise access when a publisher blocks automation or requires a subscription.

Text and media use separate routes

  • Article text: continue the authorised Camden library route in parallel where available. Record the library edition/source and citation separately from the publisher page.
  • Media: capture only media actually associated with the exact article. Keep image caption, creator/agency credit, source URL and capture time with each item. A video embed reference is not proof the video played.
  • Reading Room: keep saved source text first and AI commentary collapsed by default. Store the source attribution next to text and media, not in a detached note.

Visual checks worth automating

  • Use Playwright for repeatable desktop and narrow-phone viewport screenshots and visual comparisons. Keep reference images tied to browser/OS; rendering can vary across environments.
  • Check article title, lead, paragraph order, captions, credits, image crop/position, video placeholder and overflow at both sizes. Measure font family, size, line spacing and whether the actual font loaded; label any fallback.
  • Puppeteer is a viable alternative for headless Chrome rendering; choose one runner and make its browser version and viewport explicit.

A screenshot comparison catches layout changes; it does not prove a publisher page is complete or that a person’s phone behaves the same way.

Public-page renderer limits

Use ordinary public access only. If a site returns an access-denial response, challenge, subscription screen, or incomplete text, stop and report that outcome. Do not add cookies, a signed-in personal Chrome profile, stealth plugins, alternate controllers, or challenge bypasses.

Headless mode may receive different content or be refused. Do not label a generic technical failure as a paywall. A known subscription prompt is evidence of a gate; otherwise mark access “not established.”

Keep the evidence honest

Store metadata and bounded counts where possible: requested and final URL, timestamp, status, title/date observed, text/paragraph/media counts, viewport, and pass/reason. Avoid retaining article bodies or credentials unless a permitted workflow specifically needs the text.

Separate page fetched, text matched, media matched, visual QA, and phone check. Each is its own result.

Manual extension stays optional. The current Chrome extension can remain a fallback for a visible-media reference when a page renders only in the owner’s ordinary browser. It should not be the routine way to capture all text or images, and it still needs review before import.

Not yet built or tested: this page describes a proposed architecture. No browser was opened, no article was fetched, and no screenshots or playback were verified for this plan.
